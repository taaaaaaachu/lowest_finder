# 会員登録は招待コード制(最初の1人だけブートストラップ)

## 決定

会員登録には**有効な招待コード**を必須とする。招待コードは**ログイン中の会員がアプリ上で発行**し、有効期限(無期限も可)を持ち、**単回使用**。発行者と使用者を DB(`invites` テーブルの `created_by` / `used_by`)に記録する。

ただし**ユーザーが 0 人のときに限り**、最初の 1 アカウントは招待コードなしで登録できる(ブートストラップ)。

## 背景・理由

- 本サービスは Cloudflare Tunnel で全世界に公開される。URL を知った第三者が無制限にアカウントを作れると、データ蓄積やスクレイピング機能の踏み台にされうる。個人〜家族運用のため、登録を既知の人だけに絞りたい。
- 「`.env` に固定の合言葉」方式より、**会員が都度コードを発行し、誰が誰を招いたか追える**方が運用が柔軟かつ追跡可能。
- 招待制には「鶏と卵」問題(最初の会員を誰が招くか)がある。環境変数のブートストラップコードを持つより、**users テーブルが空なら 1 人目だけ無条件で通す**方が設定物が増えず単純。デプロイ直後に運用者が自分を登録して 1 人目を確保する前提。

## 帰結

- デプロイ後は**まず運用者自身が登録**して 1 人目を作る(URL を他人に教える前に行う)。それ以降の登録はすべて招待コードが要る。
- 招待コードは単回使用のため、1 コード = 1 招待。使い回しはできない。
- 発行者/使用者の記録は監査目的で DB に残すだけで、UI での閲覧機能は用意しない。
