# 0007 管理者リセットのパスワードは仮パスワードとし、パスワードを決めないリセットリンクも用意する

## 決定

- 管理者がパスワードを指定してリセットすると、そのパスワードは常に**仮パスワード**になる(管理者に選択肢はない)。仮パスワードでログインした会員は、新しいパスワードを設定するかパスキーを登録するまで、ログアウト以外の操作ができない。ページはサーバー側で変更画面へ戻し、API も変更に必要なもの以外は拒否する。
- 仮パスワードからの変更では現在のパスワードを求めず、直近の本人確認(ログイン直後なら済んでいる)で代える。新しいパスワードは仮パスワードと同じものを拒否する。
- 管理者は代わりに**リセットリンク**を発行できる。認証情報の初期化(パスワード・全パスキー・全セッション)は**発行時ではなくリンクを使った時点**で行う。リンクでは新しいパスワードかパスキーのどちらかを設定し、そのままログインする。
- リセットリンクは 24 時間固定・単回使用で、1 人につき最新の 1 本だけが有効。トークンは DB にハッシュで保存し、URL は発行直後に一度だけ表示する。発行後に対象者や発行者のロールが変わっても有効のまま。
- パスワードの指定・リンクの発行のどちらも、自分自身を対象にはできない。

## 理由

- 管理者が知っているパスワードを本人が使い続けられる状態は残したくない。管理者が忘れずに選ぶ運用より、常に強制するほうが確実。
- ADR 0006 はパスワードの変更に常に現在のパスワードを求めるが、仮パスワードはログインに使った直後なので、もう一度入力させても防げるものがない。
- 発行時に初期化すると、本人がリンクを使わなかった・送り間違えた場合に、本人のログインを無駄に壊してしまう。乗っ取りの疑いがあって即座に締め出したいときは、パスワード指定のリセットを使えばよい。
- 使用時にロールを確かめ直すと、リンク発行後に昇格しただけで復旧できなくなる。期限が短く取り消しもできるので、発行時点の権限で十分とした。
- 自分自身の認証情報はアカウント画面で変えられる。自分に仮パスワードを設定する意味はない。

## 帰結

- 仮パスワードの会員は、変更を済ませるまでデータの閲覧もできない。
- リセットリンクの URL は管理者がメッセージアプリなどで本人に渡す(メールは送らない)。URL を見失ったら再発行する。
