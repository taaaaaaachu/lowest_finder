# ゲストは完全クライアント完結・スクレイピングは会員限定

## 決定

**ゲストモードはサーバーと一切通信しない完全クライアント完結**とし、データはブラウザの IndexedDB にのみ保存する。**スクレイピングは会員モード限定**(ログイン必須)とし、ゲストは価格・内容量を手入力するのみとする。

## 背景・理由

- スクレイピングは `POST /scrape { url }` をサーバーで実行する必要がある(ブラウザからは CORS で不可)。このエンドポイントを Cloudflare Tunnel で全世界に公開したうえで未認証で叩けると、**SSRF(自宅LAN内部への代理アクセス)やオープンプロキシ化**の攻撃面が生まれる。NAS と同じ LAN に他の機器がある前提のため、これは看過できない。
- スクレイピングを認証必須にすることで、不特定多数からの悪用面を大きく削減できる。ゲストは手入力のみで完結するため、サーバー機能を一切必要としない=攻撃面がさらに減る。
- 副次的な利点として、ゲストモードが完全オフラインで動作し、設計もシンプルになる(サーバー登場は会員モードのみ)。

## 帰結

- ゲストは URL からの価格自動取得を使えない(手入力のみ)。この体験制約は許容する。
- 会員限定であっても、スクレイピング処理側では多層の SSRF 対策(https限定・プライベートIP宛先拒否・DNS解決後IP検証・サイズ/タイムアウト/リダイレクト上限)を実装する。
- ゲストデータは IndexedDB にあるため、会員登録時に「取り込み」で会員データへ移す導線が必要。
