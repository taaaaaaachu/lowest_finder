# 0005 会員モードをオフラインでも起動・記録できるようにする

## 状況

店頭など電波の弱い場所で使うため、会員モードでもアプリを開いて閲覧・記録したい。
従来は Service Worker が固定のオフラインページだけを返し、会員データは読み取りキャッシュのみで、書き込みはオンライン限定だった。

## 決定

- **アプリ本体**: Service Worker がビルド成果物と静的ファイルを版ごとにプリキャッシュ(cache-first)。画面遷移の HTML と `__data.json` は network-first で保存し、通信不可・5xx(オリジン停止時の Cloudflare 応答)では保存済みを返す。HTML にはユーザー情報が入るため、ログイン・登録・ログアウトの POST でページキャッシュを消す。
- **会員データ**: ユーザーごとのローカルDB(`lowest-finder-m-<userId>`)で読み書きし、書き込みは outbox に積む。同期は「outbox を順に既存APIへ再送 → 空になったら `GET /api/export` の全件でローカルを置き換え」。起動時・`online`・画面復帰・書き込み直後に同期する。
- **冪等性**: 作成APIはクライアント採番の `id` を受け付け、同じ id の再送は既存行を返す。他人の行と衝突したら 404。
- **応答の扱い**: 2xx・404 は完了(404 は削除済みとみなす)、401/403 は止めて再ログインを促す、408/429/5xx/通信不可は止めて再送、その他の 4xx は破棄して通知。
- **競合**: サーバーに届いた順の後勝ち。削除済みへの変更は破棄(削除優先)。
- **後始末**: ログアウト時に Service Worker が会員のローカルDBを削除する。未送信があるときのログアウトは確認する。

## 結果

- スクレイピングと取り込み(Import)はオンライン限定のまま。
- `+page.server.ts` を持つ画面(アカウント・管理)は、一度開いたものだけオフラインで表示できる。
- データ量が大きくなったら全件 pull を差分同期に変える。
