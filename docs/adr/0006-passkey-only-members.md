# 0006 パスキーのみの会員を認め、復旧は管理者リセットで認証情報を全初期化する

## 決定

- 会員の認証情報は「パスワード(0〜1)」と「パスキー(0〜n)」。**常にどちらか1つ以上**を持つことをサーバーで強制し、最後の1つを消す操作は拒否する。
- 「パスワード認証の無効化」はフラグではなく**パスワードの削除**とする。再び使うときは新しいパスワードを設定する。
- 会員登録(ブートストラップを含む)はパスワードとパスキーのどちらでもできる。
- パスキーのログインはユーザー名を入力しない方式(discoverable credential)とする。
- 認証情報の追加・削除には、既存の認証情報(現パスワードかパスキー)による再確認を要する。削除系の操作では、操作した端末以外のセッションを破棄する。
- ただしパスワードの変更は、パスワードを持つ会員には直近の本人確認があっても常に現在のパスワードを求める。直近の本人確認で代えられるのは、パスワードのない会員が新しく設定する場合だけ(兄弟プロジェクト stockify・warranty_remember とそろえる)。
- 端末を失くした会員は、**管理者のパスワードリセット**で復旧する。リセットは新しいパスワードを設定し、**全パスキーを削除**し、全セッションを破棄する。

## 理由

- フラグで止める方式では、再び有効にしたときに漏れたかもしれない旧パスワードが復活してしまう。削除なら「ある/ない」の2状態で済む。
- 招待制・家族規模の運用のため、メールによる復旧の仕組みは持たない。復旧窓口は既存の管理者リセットに一本化する。
- リセットが必要になるのは、端末の紛失や乗っ取りのときがほとんどである。その時点のパスキーは信用できない(盗まれた端末や攻撃者が追加したものかもしれない)ため、すべて消す。

## 帰結

- 管理者がリセットすると、対象の会員はパスキーを登録し直す必要がある。
- RP ID は公開ドメインに紐づくため、ドメインを変えると全パスキーが使えなくなる。
